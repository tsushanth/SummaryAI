Retention (code reality): everything is kept until the user deletes a recording or the account. There is no automatic purge. Recording delete removes the storage file, transcript, summary and related rows (it does not call Recall; media for bot meetings stays at Recall until account deletion or Recall's own retention **[VERIFY]**). Twilio call recordings are deleted from Twilio after download. Recall, Deepgram and Anthropic retention is each vendor's own **[VERIFY each]**.

**What account deletion does (matches `backend/src/services/accountPurge.ts`; applies once that branch is deployed).** On `DELETE /api/users/account` for the signed-in user only, in this order: (1) list what exists outside our database: storage objects, Recall bot ids, Twilio recording ids; (2) delete the audio, video, PDF and export files from Supabase Storage and check none are left; (3) stop any live or scheduled meeting bot and ask Recall.ai to delete the media it stores for each bot; (4) delete any call recording still held at Twilio (normally already deleted right after download); (5) delete the database rows (recordings, transcripts, summaries, Q&A, todos, meetings, bot runs, live transcripts and insights, phone calls and verified numbers, share links, folders, calendar connections, integration settings, profile and subscription fields); (6) delete the sign-in account last. If a processor step fails, the account is still deleted and the remaining processor deletions are retried automatically with backoff (up to 10 attempts, then an alert to us). If our retry record does not exist (migration not applied) the request instead fails with an error and nothing is deleted, so the user can retry. We keep a deletion log with counts and timestamps only: a one-way hash of the account id, no content, and the account id itself is removed once the purge completes. **Not covered by account deletion:** Deepgram and Anthropic (we send content for processing and store nothing there; their own retention applies **[VERIFY]**), Resend (emails already sent **[VERIFY retention]**), Google/Microsoft calendar grants (we delete our stored tokens but do not call the provider to revoke; the user can revoke in their Google or Microsoft account **[VERIFY: add revoke call or state this]**), Stripe and RevenueCat records for subscribers (**[VERIFY: not touched by this change]**), Supabase backups **[VERIFY: retention]**, and messages or exports the user already sent to Notion, Slack or webhooks.

User controls that exist: delete a recording; delete the account (files, processor media and database rows, see "What account deletion does"); export transcripts and summaries (web `ExportMenu`); revoke a share link; disconnect a calendar; remove an integration; turn auto-join off per meeting; choose summary language and template.
